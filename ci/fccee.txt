FCC-ee backend CI
=================

The existing backend job (job id lcg) now runs in the Key4hep 2026-04-08
release on EL9. ROOT/TGeo and DD4hep remain enabled, and the unit, installed
shared-library and standalone ingestion checks remain in the job. Its Conan
and compiler caches are separate from the former LCG 109 environment.

The representative suite is CLD_o2_v08, ALLEGRO_o1_v01, IDEA_o1_v03 and
IDEA_o2_v01 from the installed k4geo compact files. Each detector is loaded in
a fresh Python worker using read_semantic with dd4hep.useGlobalDetector=true
(required by ALLEGRO readouts), then written without selection into full NHS9.
The unified steering script shares a bounded process pool across all detector
inputs, with four workers by default and one input per worker lifetime. The output is reloaded
and validated with inspect summary. IDEA imports must retain at least 200
million occurrences; reduced historical fixtures cannot pass this check.

Tessellation is deliberately bounded: inspect tree --depth 2 supplies the
placement boundaries for a generated config which drops deeper descendants.
The entire source is still imported and serialized first. Tessellation tests
shared selection and lowering on the imported scene's upper placement levels,
not full-detail detector rendering or the historical hand-authored configs.
The world solid is hidden, every retained node receives a material, and
boolean failure is an error. The gate requires matching retained/render node
counts, nonempty triangle geometry and valid mesh references.

PYTHONPATH=build/Release/python .venv-key4hep/bin/python ci/detectors.py --suite fccee

The Key4hep build enables NODEHAMMER_BUILD_PYTHON with the stack's Python
interpreter in a uv-managed virtual environment containing the dev dependency group:

  uv venv --python "$(command -v python3)" .venv-key4hep
  uv pip install --python .venv-key4hep --group dev
Loading, writing, configuration and rendering use the direct Python bindings.
Tree and summary inspection use nh.cli.run in-process, since those operations
have no scene-level Python API. No stage launches a CLI subprocess.

The script discovers compact files via K4GEO or CMAKE_PREFIX_PATH; an explicit
--geometry-root can supply the directory containing FCCee/. --suite fccee
selects only FCC-ee inputs; --jobs controls concurrency. The CI job has a
90-minute bound. Ordinary detector failures do not stop other inputs; a native
worker crash breaks the pool and marks unfinished inputs failed. summary.json, per-stage logs, inspection/render JSON, generated
configs and compressed NHB geometry are uploaded as fccee-results even on
failure, retained for seven days. Geometry is not committed.

The local harness checks run with:
  python3 -m pytest ci -q

Gallery publications use the authored simplified/detailed pair for each model,
not the smoke scene. Each preset is selected and packaged from the full NHB;
its result embeds the smoke report separately and carries no smoke triangle
counts at the top level. The detailed IDEA configs explicitly drop dual-readout
calorimeter internals. Selection guards reject more than 200,000 simplified or
5,000,000 detailed placements before packaging.
